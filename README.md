# my-app

## 1. サービス概要

忙しい保護者が、自分と家族の排便状況をカレンダーに記録し、「最後に出た日」をすぐ確認でき、病院や園で「いつから？」と聞かれたときに、正確に答えられる安心感を届けるアプリです。
MVPでは、まず自分の記録のみでアプリの価値を確かめ、最終的には自分と家族の記録を目指します。
本リリースでは、排便がない日も、夜の問いかけ（プッシュ通知）でアプリを開くきっかけをつくり、排便状況の把握や記録漏れを防ぎます。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

いつ：自分や家族が便秘や下痢になったとき。

どんな状況で：自分だけでなく、家族にも便秘や下痢の症状が出たとき。
誰から、どんな順番で、何日かけて症状が出たのかを記録していなかったため、まだ症状が出ていない家族がいつ頃つらくなりそうかを予想できず、食べられそうなものを事前に買いためておくこともできなかった。

どんな気持ちになったか：ちゃんと排便を記録していれば、病院受診時、医師へ正確に伝えることができ、便秘や下痢で入院になってしまったり、自分が辛い時や家族が辛そうにしている時に食べられそうなものを買いに行く手間も無くせたのではと、後悔した。

### 2-2. なぜそれが「気になった」のか

自分の性格：子供の行事や習い事、自分の病院受診日や夫の予定を覚えておくことはできるが、便秘や下痢の把握まではなかなかできない。
また、排便の記録を誰でも見れるカレンダーやスケジュール帳に書くのは、見られた時のことを思うと恥ずかしくてできない。

過去の経験：病院受診時、医師からいつ頃から便秘をしているか聞かれた際、はっきり回答できず、「様子を見ましょう」と言われ帰った後、夜中に腹痛で救急搬送され、大量の便が腸に溜まっていたことが分かったことがある。
また、子供が通う幼稚園で感染性胃腸炎が流行し、子供が感染した。
つらくて、お母さんにそばにいて欲しいと願う子供を自分の母に預けて、食べられそうなものや、薬をスムーズに飲めるようにするゼリー、流せるお尻拭きなどを買いに行かないといけなくなり、必要なものを事前に備えることができなかった。

大切にしている価値観：家族を想う気持ち。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

自分や家族が病院受診したり、園や学校を休むとき、いつから便秘や下痢になったか正確に医師や先生達に伝えることができない。

家事や育児、仕事やそれらに関連した予定把握を行なっていると、自分や家族の排便状況を覚えておく余裕がない。

### 3-2. 本当に解決したい課題は何か

- なぜ解決したい？
  → 便秘や下痢になったとき、病院や園で「いつから」なのか確実なことを言えない
- なぜ確実なことを言えない？
  → 排便の記録をしていないから
- なぜ記録しない？
  → カレンダーなど、人から見られる可能性が高い所に書くと、家族や友人に見られて恥ずかしいので書けない
- なぜ書けない？
  → 人に見られずに、すぐ記録できる場所がないから

→ 本当に解決したい課題：忙しさや辛さで余裕がなくなると、自分や家族の排便状況を覚えておいたり記録したりできず、いざ病院や園で聞かれたとき、正確に答えられない。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

**年齢設定**

- 年齢：20〜30代
- 理由：20〜30代は自分のことだけではなく、細々とした家族の予定も把握しておく必要があり、体調管理に関する記録が疎かになりやすいため、アプリの必要性を感じてもらいやすいのではないかと考えた。20代以下は自分や保護者が排便状況を把握している可能性が高く、30代を超えると、細々とした予定や体調管理に関する記録方法をすでに確立している可能性があり、このアプリの必要性を感じにくいのではないかと考えた。

**生活・状況設定**

- 生活・状況：幼稚園や学校に通う子供がいて、家事・育児・仕事をしながら家族全員の予定を把握している20〜30代の保護者。
- 理由：予定の管理に手一杯で、排便状況の記録まで手が回らない。夜寝る前に1日の振り返りとして簡単に記録・確認できれば、病院や園で聞かれたときに答えられる。

**環境設定**

- 環境：家族が見られるカレンダーやスケジュール帳が家にあり、スマホを夜寝る前に使う家庭。
- 理由：カレンダーに書くと家族や来客に見られて恥ずかしい。個人のスマホのアプリなら、他の人に見られずに記録できる。

### 4-2. 自分とユーザーの距離

- 自分自身
- 過去の自分
- 身近な誰か

選んだ距離：自分自身

なぜその距離感なのか：
子育て中で自分や家族の排便状況を把握する余裕がなく、受診時に正確に伝えられず後悔した経験があるため。ターゲットは、自分と同じ状況にいる人であり、自分が一番のユーザーであると考えた。

その距離だから、どう検証するか：
自分自身がユーザーなので、まずMVP（最小限の機能で価値を確かめる試作版）を自分で毎日使い、「通知がなくても1週間続けられるか」と「受診時に最後に出た日をすぐ答えられるか」を確かめる。
ただし、自分だけだと「自分には便利」という思い込みになりやすいため、同じ世代で、幼稚園や学校に通う子供がいる保護者の友人にも使ってもらい、1週間続けられたか、記録の手間は負担ではなかったかを聞く。

### 4-3. 実際に使われる可能性について

まず最初に使ってくれそうな人は誰か？：幼稚園や学校に通う子供がいる20〜30代の保護者

その人は、どんな場面でこのアプリを思い出すか？：自分や子供の便が出たとき。

今の生活の中で、代わりに使っているものは何か？：カレンダー

それを置き換えてまで使う理由はあるか？：病院受診時、カレンダーの写真を撮り忘れ、がんばって記録していたのに排便状況の答えが曖昧になってしまう。また、カレンダーに書くと、家族や友人が来た時に必ず「この赤丸なに？」と聞かれ、「うんこが出た日を記録している」と答える必要があるため。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか：
病院や園で「いつから？」と聞かれて答えられず、困ったり後悔したりしたときに、記録する方法を探し始めてアプリの存在を知る。

最初の一歩（登録・導入）で、ユーザーは何をする必要があるか：
自分の名前、メールアドレス、パスワードの登録。（名前は全て仮名可）
本リリースで、同居する家族の名前の登録を追加。

利用を続ける理由は何か？（習慣・必要性・価値）：
便秘や下痢で自分や家族の体調が悪くなり、病院や園で「最終排便日」を答えられず困った経験から「記録することの大切さ」を感じ利用を続ける。

MVPには通知機能がないため、次の工夫で継続を支えます。

- 開いてすぐ記録でき、1〜2タップで終わるシンプルな仕様
- 毎晩開いて記録しても苦にならず、アプリを開く習慣化をつけることができるシンプルで簡単な仕様
- カレンダーで「最後に出た日」をすぐ確認できる

MVPでは、「通知がなくても1週間続けられるか」も検証します。

本リリースで、夜寝る前にプッシュ通知で「今日のおなかの調子はいかがでしたか？」と問いかけが来ることで、排便がない日もアプリを開き、カレンダーで「何日出ていないか」を確認する。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

- サービス名：ウンログ
- URL：https://play.google.com/store/apps/details?id=com.mynew.unlog&pcampaignid=web_share
- どんなことができるか：
  - ログ：うんこが出た日と便の状態を、イラストで選んで記録できる。
  - カレンダー：記録した便の状態を、カレンダーで確認できる。
  - 占い：生年月日をもとにした占いが、排便の有無に関係なく毎日表示される。
  - レポート：ウンスコアという0〜100までの独自のスコア表と排便回数、登録した腸活食材が表示される。
  - ウントーーク：匿名でつぶやき投稿をすることができ、つぶやきに共感ボタンを押したり、コメントを書いたりすることができる。
  - my腸活：10問の質問に答えると、自分の腸タイプを知ることができる。
  - ウンチップ：今まで獲得したポイント数と、毎日GETで5ポイント、Xへのポストで50ポイント、いいね！して50ポイント、レビューして100ポイントの表示があり、実行するとポイントがもらえる。排便記録をすると5ポイント獲得できる。有効期限は6ヶ月。5,400ポイント（300円）からAmazonギフト券へ交換できる。
  - ウンコレ：オリジナルキャラクターが表示されるだけで、何に使うのかの説明もないため、使い方は不明。
  - ウン知識：1日1回、便に関する豆知識が表示される。
  - 観便検定：便や腸活に関する問題が5問出題され、知識を得ることができる。5問全て正解しないと次の5問には進めない。

### 5-2. それでも自分が作りたい理由

既存サービスがある中で、

- なぜ満足できなかったのか：便の状態をイラストとアプリ内のカレンダーに残せる点は良かった。しかし、「楽しく継続できる機能」として占いや、ポイントを受け取れる機能、観便検定など、さまざまな機能があることで、どこに排便記録を書くのか分かりづらく、排便の記録以外に促されて登録した腸活食材がどこに反映されているのかも簡単に見つけられなかった。また、記録よりも占いや検定などのコンテンツをユーザーに楽しませることがメインになっているように感じ、「楽しく継続できる機能」として活用することができなかった。

- どこに違和感があったのか：ウンログは、占いやログインポイントがあるので、排便がない日でもアプリを開く理由はある。しかし、それはどれも占いやポイント獲得を楽しむためで、「何日出ていないか」を確認するためではない。排便がない日こそ「何日出ていないか」を確認する必要があるのに、その確認を促す仕組みがなく、アプリを開く目的が違うというズレを感じた。

### 5-3. 差別化

私のアプリの差別化ポイント：MVPでは、記録のない日は「出ていない日」としてカレンダー上で一目で分かるので、排便がない日でも、カレンダーを見れば最後に出た日と何日出ていないかを自分で確認でき、病院受診時に「いつからか」を答えられる安心感が得られる。
本リリースでは、家事・育児・仕事・予定の把握で余裕のない保護者が、夜寝る前に「今日のおなかの調子はいかがでしたか？」と問いかけられるだけで、排便がない日でも自分や家族の排便状況を振り返ることができる。また、便秘や下痢で体調を崩し、病院受診時や園を休むときに「いつからの症状か」を答えられる安心感が得られる。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

行動の変化：アプリを毎日開いて排便状況を確認する習慣が付く。

気持ちの変化：「ちゃんと記録していれば」という後悔や不安が減り、受診時や家族の不調時にも落ち着いて対応できる安心感が得られる。

考え方の変化：排便の記録を「恥ずかしいもの」ではなく、家族の体調管理のための当たり前の習慣だと考えられるようになる。

### 6-2. 価値を一文で表す

「このサービスは、家事や育児、仕事で忙しい人が、自分や家族の「最後に排便した日」をすぐに答えられるようになるサービス」

MVPでは、検証する範囲を「自分の記録のみ」に絞ります。「最後に出た日」を表示する専用の機能は作らず、カレンダーに記録した日・記録のない日を見るだけで、自分の「最後に排便した日」をすぐに答えられるかを確かめます。家族の登録・記録は本リリースで追加します。

## 7. このアプリで実現すること

### MVPで作る機能（自分の記録のみ）

- ユーザー登録・ログイン・退会機能
- 便の状態を硬便・普通便・軟便・下痢から選べる機能
- カレンダーに排便状況を登録できる機能（記録のない日は「出ていない日」と判断できる）
- カレンダーに登録した情報を消去できる機能
- カレンダーで記録を確認し、最後に出た日を自分で見て答えられる

### 本リリースで作る機能

- 家族登録機能
- 家族名を選択して排便状況を記録できる機能
- 夜寝る前の問いかけ（プッシュ通知）機能
- 音声で排便状況を記録できる機能

## 8. このアプリの懸念点とその対策

### 懸念点①

- 何が問題になりそうか：毎日の記録が面倒になり、使い続けてもらえなくなる可能性がある。

- なぜそう思うか：想定ユーザーは、家事・育児・仕事で余裕がなく、排便状況の記録まで手が回らない人である。記録の手間が大きいと、忙しい日や体調が悪い日に記録が途切れ、いざ病院や園で聞かれたときに答えられない、という課題が解決できなくなる。

- そのために考えている対策：MVPでは、便の状態を硬便・普通便・軟便・下痢から選ぶだけにして、入力の手間を小さくする。本リリースでは、音声で記録する機能を追加して、さらに記録を簡単にする。また、夜寝る前の問いかけ（プッシュ通知）で、アプリを開くきっかけと、記録を思い出すきっかけをつくる。

### 懸念点②

- 何が問題になりそうか：プッシュ通知の文面がロック画面に表示され、家族や友人に見られてユーザーが恥ずかしい思いをする可能性がある。

- なぜそう思うか：このアプリは、カレンダーに書くと家族や来客に見られて恥ずかしい、という理由から作ろうとしている。通知の文面が見られてしまうと、カレンダーに書く場合と同じ恥ずかしさが生まれ、通知をオフにされたり、アプリを使わなくなったりして、アプリを開くきっかけが失われる。

- そのために考えている対策：通知の文面には「うんこ」などの排便を直接示す言葉を使わず、「今日のおなかの調子はいかがでしたか？」という、体調を気づかう表示にする。見られても何の通知か分からないようにする。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8.1
- DB：PostgreSQL
- デプロイ先：Render（開発環境の構築にはDockerを使用）
- 使用予定ライブラリ：
  - Devise：ユーザー登録・ログイン・退会機能を一から作らずに追加するため
  - simple_calendar：排便状況を表示・登録するカレンダー画面を作るため
  - RSpec / FactoryBot：学習で使っており、機能が正しく動くかをテストするため
  - ※ 各ライブラリは、最終更新日とサポート状況を確認済み（Devise：2026年1月、simple_calendar：2025年1月）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | 現在学習中で、MVPを短期間で作りやすく、困ったときに調べられる情報も多いため |
| Laravel（PHPのフレームワーク） | 不採用 | 学習していない言語で、キャッチアップに時間がかかるため |
| Rails単体（画面もRailsで作る） | 採用 | MVPの機能（記録・カレンダー表示）は、Railsだけで実現できるため |
| React | 不採用（本リリース後に検討） | 学習はしたが、MVPには必須ではなく、導入すると完成までの時間が延びるため |
| PostgreSQL | 採用 | 公開時にも使いやすく、デプロイ先のRenderで利用できるため |
| SQLite | 不採用 | 開発中は手軽だが、公開後のデータ保存には向かないため |

- 今回チャレンジしたい点：カレンダーに排便状況を表示・登録する機能と、ログイン・退会機能を、ライブラリを使って自分の力で実装すること。
- 不安な点：本リリースで追加するプッシュ通知機能は、実装した経験がありません。MVPが完成してから調査します。

### 10-3. キャッチアップ不足の懸念

1. **プッシュ通知が未経験**
   本リリースの機能です。MVPの完成後に、必要な技術を調べてから実装方法を決めます。
2. **カレンダー表示の実装に時間がかかる可能性**
   simple_calendarの使い方を先に小さく試し、難しければ表示方法を簡単なものに変更します。
3. **「音声で記録」の不安点**
   本リリースの機能です。
   - ブラウザや端末によって、音声認識が使えるか分からない（対応状況を調べて確認する）
   - 「排便」「下痢」などの言葉を、雑音や子供の声がある中で正しく聞き取れるか分からない
   - 誤って認識された場合に、確認・修正できる画面にする必要がある
   - 音声データが外部に送られる場合、健康に関わる情報の扱いに注意が必要
   - 外部サービスを使う場合の費用
